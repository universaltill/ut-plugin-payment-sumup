## 2. ut-plugin-payment-sumup (v1.5.3 -> v1.6.0, branch fix/fable-sumup)

### What shipped
- #6598: a bounded (8) `refunds` record keyed by event id (`sending`/`done`), written before the call. A repeat of a finished refund is answered from the record. A retry after a lost reply goes to the same leg only, and only for a full refund of that leg. A partial retry declines `refund_outcome_unknown`. A 5xx now counts as `network_error` (unknown). A definite failure clears the record.
- #6599: explicit `sumup_test_mode` (choice, default `off`, global). Without it, a missing key or reader declines `no_api_key`/`no_reader`. Refunds route by reference (`demo-` = no call; a real ref always goes to the API). Test mode approves `demo-refund` only on `unknown_original_payment`.
- #6606 / #6600: same map copy and decline answer as Stripe.

### Verification
- `go test ./...`, wasip1 vet, wasm build, `validate.sh` (ok v1.6.0), `guard-plugin-i18n.sh` ok (de/tr missing the 4 new keys, which come from Weblate).
- Mutations (all killed): missing reader -> demo again -> `TestAuthorizeModeDecision` fails; record guard disabled -> 4 `TestRefund*` lost-reply tests fail; `recent` written back -> `TestSaveAuthorizeResultDoesNotMutateAnswer` fails.

### Findings
- Low (accepted, safe direction): `legTotal` (`src/refund.go:88`) returns `Amount + TipAmount`, but core's `amount` already includes the tip. A lost-reply retry of a full refund on a tipped leg is declined `refund_outcome_unknown` instead of resent, so #6598 scenario 3 is still open for tipped legs. Fix with the recent.go:160 double count.
- Low (accepted): the record holds 8 entries; more than 8 refunds between a lost reply and its retry evicts the guard.
- Low (product note): `sumup_test_mode` is shop-wide (global). Switching it on to test one till turns every till into no-charge demo, even with a reader paired. Consider register scope or a visible banner.
- Behaviour change for existing installs: a register with no reader (formerly silent demo) now declines `no_reader`. This is the intended fix and is in the README and description.

### Verdict
Approve.
