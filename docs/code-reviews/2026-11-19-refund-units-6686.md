# Review: SumUp refund amount units (ut-docs#6686)

Card: universaltill/ut-docs#6686 (complexity:easy). Version 1.8.1 (test + docs only; README ships, so the patch bump is required).

## Finding
The plugin refunds through `POST /v0.1/me/refund/{txn_id}` with `{"amount": <major-unit decimal>}` (`refundOne` → `minorToMajor`). That is **correct for that endpoint**, so no production code changes.
- Evidence: SumUp's OpenAPI-generated Go SDK `sumup/sumup-go` (synced from SumUp's spec). Before sync commit `113455f` (late April 2026), `TransactionsRefundParams.Amount` for `/v0.1/me/refund/%v` is `*float32` with no unit stated. Its sibling fields `amount`, `tip_amount`, `vat_amount` are float major units, and refund `Link.max_amount` is documented "in major units". From `113455f` on, the spec has only `POST /v1.0/merchants/{code}/payments/{id}/refunds`, with `Amount *int` "in minor units … `500` for EUR 5.00".
- developer.sumup.com and api.sumup.com are not reachable from this session, and there is no sandbox key here. The 2026-11-17 sandbox record (ut-docs#6561) shows only a full refund answering 204. So the partial-amount unit is inferred from the schema, not proven in the sandbox. The docs now say so.
- Risk: SumUp's spec no longer lists the legacy path. The migration to v1.0 (integer minor units, merchant code + payment id, a sandbox partial refund) is filed as **ut-docs#6695**.

## What shipped
- `src/refund_units_test.go`: exact request body for a 12.50 full refund (`12.5`), a 4.50 partial leg via `refund_amount` (per-leg path), a reversal, a reversal carrying `refund_amount` (still the whole amount), 0.01 and 19.99. It also checks the ledger fake's refunded minor units.
- README "Refund" bullet and CLAUDE.md refund note: the evidence, its limits and the v1.0 difference.
- ut-docs `reference/uk-card-terminal-integrations-2026-11.md`: open question 6 answered.

## Review
Independent review by a different model from the author (Opus authored, Sonnet reviewed). The reviewer re-checked the SDK claims in the clone itself. Verdict: no blocking findings.
- **F1 (medium, fixed):** the notes stated "major units" as documented fact, but the schema gives only a float type plus the sibling fields. The wording is softened in the README, CLAUDE.md and the test comment, and now says only a full refund was sandbox-tested.
- **F2 (medium, deferred → ut-docs#6695):** the legacy path is gone from SumUp's spec. Once SumUp removes it, refunds decline. The "just drop `minorToMajor`" advice was too glib, so the notes now point at the card (other path params are needed).
- **F3 (low, fixed):** the spec-change date was 2026-04-24. It is now "late April 2026", since the sync commit is dated 04-27 and its parent 04-24.
- **F4 (low, fixed):** the reversal case could not catch a reversal wrongly going per-leg. Added a reversal that carries `refund_amount`.
- **F5 (low, accepted):** `refund_legs_test.go` already pins the integer-valued bodies. The new test adds 12.5, 0.01, 19.99 and the reversal cases.
